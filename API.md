# Mission Possible resources API

The machine-readable contract is served at `/api-contract.json`. Run `node scripts/generate-api-client.mjs` after updating operation paths. Shared runtime validation and TypeScript resource models live in `lib/contract.ts`; generated endpoints are used by the data hook and resource actions.

Members sign in through the hosting platform. The dispatcher supplies verified identity; raw client IDs are never accepted. Clerk has not been integrated in this release. The first signed-in member becomes the initial administrator through an atomic singleton insert. The admin portal uses an independent password and eight-hour HttpOnly session.

## Operations

| Method | Endpoint | Access | Result |
|---|---|---|---|
| GET | /api/resources?type=training | Member | `{ resources: Resource[] }` |
| POST | /api/resources | Admin session | 201 `{ resource: Resource }` |
| PATCH | /api/resources/{id} | Admin session | 200 updated fields |
| DELETE | /api/resources/{id} | Admin session | 204, deletes completion records too |

POST and PATCH require the complete editable resource object, including nullable scheduledAt. There is no draft state: saving publishes immediately. All categories are validated against resource type. URLs must use HTTP or HTTPS and are opened externally; the app does not download or upload videos.

```json
{
  "type": "training",
  "title": "Handling objections",
  "description": "A practical conversation workshop.",
  "category": "Skill Trainings",
  "url": "https://example.com/workshop",
  "scheduledAt": null
}
```

IDs are generated by the server. Dates are ISO 8601. Resource responses also contain created_at and updated_at. The optional schedule is displayed in the member's local time zone. Daily reports and leaderboard periods use UTC. Week-over-week growth compares the current partial week against the full previous week and is labeled accordingly.

Errors use `{ "error": "message" }`: 400 invalid input, 401 no valid sign-in, 403 missing admin session or wrong origin, 404 missing resource, 409 duplicate daily response, 415 wrong content type, 429 too many admin login attempts, 503 storage or temporary server failure.

## Additional flows

`GET /api/data` returns the signed-in profile, daily reports, leaderboard inputs, resources, and completion records. Members see only their own learning completions; the admin session sees all team completions. `POST /api/responses` accepts integer enrollments, confirmations and calls from 0 to 100000; the server stamps the date and computes score. A database uniqueness constraint enforces one report per member per UTC day. `POST /api/progress` accepts resourceId and complete to record or undo learning completion.

`POST /api/admin/login` accepts email and password; first-time setup additionally uses setup:true and requires the authenticated initial administrator. `POST /api/admin/logout` revokes the current session. Passwords use salted PBKDF2-SHA256; tokens are stored only as SHA-256 digests. All writes enforce same-origin requests. Admin login attempts are rate-limited.

## Verification

Local integration verification covers unauthenticated access, protected publishing, negative counts, 8.4-point scoring, duplicate rejection, resource create/read/update/delete, completion tracking, cascade deletion and session revocation. Production begins empty; local test data is never deployed.
